# KMP App Scaffold

当前为设计草案，尚未安装；下文脚本、图标资源、测试与性能工程是模板的交付要求，不能报告为已经实现或通过验证。

## 1. 适用边界

- 适用：空目录新建 KMP 双端应用；需要一套能直接演示的设计系统与假数据。
- 不适用：在既有工程里加页面或改功能；Android-only、XR、小程序、Web 工程；工程迁移。

## 2. 输入参数

必须：

| 参数 | 说明 |
| --- | --- |
| 应用名 | 中文显示名，用于 launcher / Info.plist |
| 工程名 | 英文 PascalCase，用于 Gradle 模块与 Xcode 工程名 |
| 包名 | Android applicationId，反向域名格式 |
| Bundle ID | iOS Bundle Identifier，反向域名格式 |
| 目标目录 | 必须不存在或为空 |

可选：品牌色（默认 `#FF6740`）、模板版本（默认最新稳定版）、是否保留示例业务（默认保留）、图标设计来源（Figma 节点或本地 SVG）、性能预算配置（默认使用模板已验证的设备基线）。

缺参数时逐项提问，禁止猜测包名，禁止覆盖非空目录。

## 3. 前置检查

1. 目标目录不存在或为空；非空时停止并请用户指定新目录。
2. 包名与 Bundle ID 通过反向域名格式校验。
3. 模板来源可用：读取模板目录下 `template.version`，确认落在本 skill 声明支持的区间。
4. 记录模板版本、模板提交号，写入生成报告。
5. 检查图标资产与来源清单完整，确认性能预算确有对应设备、构建类型和测试场景；没有基线时安排首次采集，不虚构“已达标”。

## 4. 执行流程

1. 复制模板到目标目录，排除 `.git`、`build`、`.gradle`、`DerivedData`、`*.iml`、`local.properties`、`.idea`。
2. 按 [template-layout.md](template-layout.md) 的占位符表替换文件内容和文件名，替换后全文检索 `__` 残留。
3. 运行模板自带 `scripts/check-generated.sh <target>`：文件存在性、占位符清零、包名一致、主题色与图标资产已注入。
4. 依次执行构建与测试门禁（见第 5 节），任一失败先修复再继续。
5. 双端启动验证：Android 有设备则安装启动；iOS 构建后安装到已启动模拟器并截图。
6. 验收图标与组件展示页，运行单测与性能采集，按下文专项要求记录证据。
7. 输出生成报告（见第 8 节）。

## 5. 验证门禁

模板使用与 PandaVideo 一致的双端结构，命令按实际生成路径执行：

- 共享层：`:shared:jvmTest` 与 `:shared:testAndroidHostTest`
- Android：`:app:assembleChinaDebug`；`adb devices` 有设备时安装并启动确认首屏
- iOS：`source mobile/.xcode.env && ./gradlew :shared:linkDebugFrameworkIosSimulatorArm64`；再 `xcodebuild -project ... -sdk iphonesimulator -configuration Debug build`；`xcrun simctl install/launch booted` 后截图
- 冒烟清单：首屏渲染、列表滚动、详情进入与返回、搜索输入、明暗切换
- 设计验收：图标轮廓、线宽、视觉尺寸、选中/禁用态、深浅色、RTL 方向及无障碍标签；弹窗字号、系统安全区、键盘弹起、大字体均需检查。
- 测试验收：读取测试结果 XML，报告用例数、失败、错误和跳过数；跳过或缺少结果不能计为通过。
- 性能验收：执行 `scripts/profile.sh` 的指定场景，把原始采集文件和测量条件写入性能报告；与相同设备、构建类型的基线比较。
- Kotlin/Native 目录只读导致链接失败时，把 konan 分发复制到可写目录并用 `-Pkotlin.native.home` 指向，不要改系统目录权限

所有门禁必须真实执行并给出结果，不允许以“应该可以”代替。

## 6. 生成物要求

结构见 [template-layout.md](template-layout.md)，硬性要求：

- 设计系统 token 单点定义（颜色、字号、间距、圆角），明暗两套；组件只保留一种主流风格，不做变体矩阵。
- 假数据集中在 `SampleData.kt`，支持移除示例业务；图标必须交付真实矢量资产，业务演示图片使用可分发的本地资源，启动演示不依赖外网。
- 最小链路：首页列表 → 详情 → 返回；搜索页包含历史、联想、直接搜索行；收藏/历史用本地 KV 验证持久化。
- 每个列表页可呈现四态：骨架、空、错误、成功。
- 隐私与权限最小化，Manifest / Info.plist 只保留实际使用的项。

### 图标设计与资源

- 内置返回、关闭、搜索、清除、主页、分类、收藏、历史、设置、刷新、删除、勾选、更多等基础图标，并配套 AppIcon 与启动标识；视频类图标作为可选扩展。
- 统一默认 24dp 画布、线宽、圆角、视觉中心和尺寸 token；明确哪些图标可调色、哪些保持品牌原色。视觉尺寸与触控尺寸分开定义，遵循平台最小触控尺寸要求。
- 提供 SVG 原稿、共享 `ImageVector` 或 Compose 矢量资源、Android 自适应图标、iOS AppIcon 资源。禁止用 emoji、字体字符或临时占位图代替设计图标。
- 记录每项资产的稳定 ID、设计 URL/节点、来源、许可或使用授权依据、导出参数和文件路径。取得源文件后再转换，不能因 Figma 限流而猜测形状并宣称与设计一致。
- 在 `DesignGalleryScreen` 展示组件和图标的正常、选中、禁用、深浅色状态。需要镜像的是方向图标，文字、数字与品牌标识不可一起镜像。

### 单元测试与平台回归

- `commonTest` 覆盖导航返回、状态恢复、搜索去空格/去重、收藏与历史规则、分页边界、空结果、失败重试、取消与过期响应。测试可观察行为，不测试私有实现细节或为凑覆盖率重复断言。
- 协程测试使用虚拟时间和可控假仓库，禁止真实网络与固定 sleep；至少验证“旧搜索晚返回不能覆盖新搜索”和“取消任务不被当成加载失败”。
- 分别测试 Android/iOS KV 适配器的写入、读取、删除与重新创建后的数据保留；内存假实现的通过不能代表平台持久化通过。
- UI 回归覆盖图标状态、明暗主题、字体放大、输入键盘、安全区、返回和重试；截图测试固定字体、设备尺寸、主题和假数据，基准图片经过视觉确认后才更新。
- 默认执行全部模板单测。覆盖率用于发现遗漏；若设置门槛，限定关键业务模块并记录配置，不能把百分比替代正确性验收。

### 性能与质量基线

- 默认测量冷/热启动到可交互首屏、列表滚动与页面切换帧时间/卡顿率、重复进入返回后的内存、图片缓存占用、包体积。涉及播放或持续后台任务时增加功耗与后台资源占用场景。
- Android 配套独立 `benchmark` 模块和 Macrobenchmark 场景，区分 TTID 与 TTFD；只有首屏数据和交互就绪后才调用 fully-drawn 标记。提供 Perfetto trace 供回归分析。
- iOS 配套 XCTest 启动性能场景与 Instruments 采集说明，覆盖帧卡顿、内存和重复导航；自动测不到的指标标为待测，不能用 Framework 编译结果代替性能测量。
- 使用 release/benchmark 优化构建，在固定真实设备上至少重复 10 次，保留原始样本并报告中位数、P95 和样本数。记录设备/OS/刷新率、构建标识、数据集、缓存条件与温度状态。
- 模拟器用于功能冒烟，性能数据单独标注，不与真机基线混比。比较前固定假数据、网络条件及后台负载；冷/热启动分别统计。
- `performance-budget.json` 定义指标、单位、场景、绝对预算及允许退化幅度；首次无基线时先建立测量结果。只有条件匹配才执行回归门禁，不能放宽预算来消除失败。
- 缺少设备或采集工具时仍交付可执行测试入口和采集步骤，报告“未测”和原因；编译通过、无崩溃与性能达标分别报告。

## 7. 约束

- 默认不发起真实网络请求；如需网络层，base URL 走配置且默认指向假数据源。
- 不生成密钥、证书、真实 `.env` 值；debug 签名只用本地 debug keystore。
- 日志统一封装，禁止输出 URL、Token 等敏感字段。
- 幂等：目标目录已存在时只补差量，不覆盖用户改动；冲突即停止并报告差异。
- 生成代码的公共 API 使用英文 KDoc，界面文案使用中文。

## 8. 生成报告模板

```
应用名 / 工程名 / 包名 / Bundle ID
模板版本 / 模板提交号 / 品牌色
创建文件数 / 占位符替换数 / 残留检查结果
门禁结果：shared 测试（通过/失败）、Android 构建（通过/失败）、iOS 编译（通过/失败）、启动验证（通过/失败/无设备）
设计验收：图标来源与许可清单 / 组件展示页 / 双端截图 / 未验收项
单测：各平台用例数 / failures / errors / skipped / 结果文件
性能：设备与构建类型 / 场景 / 样本数 / 中位数与 P95 / 预算比较 / 原始 trace 路径 / 未测项
截图路径
下一步 TODO：接真实数据源、品牌定制、补隐私声明及未完成验收
```

## 9. 维护方式

- 模板放在独立仓库，带 `template.version` 与 CHANGELOG；skill 只声明支持的版本区间，不内置模板本体。
- 模板升级后先跑一遍本 skill 的全量门禁，再更新支持区间。
- 生成工程与模板的差异只允许“参数替换”和“删除示例模块”，新增能力必须回到模板仓库。
