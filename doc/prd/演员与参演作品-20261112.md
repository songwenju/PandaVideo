# 演员与参演作品

日期：2026-11-12

状态：用户已授权并完成共享实现；双端构建、Android 搜索与演员页流程验证通过

范围：PandaVideo 移动端，共享 Android / iOS 交互

## 目标与来源

用户需求：“演员。带头像和名称。然后点击演员能知道他演了哪些电影、电视剧。”

用户补充：“之前那个给的一些 figma 里面有这些设计稿吗？另外要做成这个功能，通过演员来搜索他演的电影。”

提供「搜索演员／点击影片演员 → 参演作品 → 影片播放」的浏览路径。用户已授权按本方案实施。

工程依据与数据限制见 [技术方案](演员与参演作品技术方案-20261112.md)。人物候选来自豆瓣，参演关系来自 Wikidata。只展示已收录关系，不承诺完整履历。

## 首版交互

1. 影片详情的信息区域增加「演员」横向列表。每项为圆形真实头像与姓名，紧凑排列；核对当前影片与人物出演关系后，点击整张卡片进入演员页。无法确认身份时保留姓名与人物图标。
2. 演员页顶部显示头像、姓名，下面是「全部 / 电影 / 电视剧」切换与作品海报列表。选中态沿用应用橙色，作品显示名称、可用年份和出演／配音关系。当前资料源不提供评分，保持空值。
3. 按年份从新到旧展示来源已确认的参演作品；年份缺失的作品排在最后，不编造年份或评分。
4. 完成豆瓣影片 ID 与本地标题核对的作品沿用现有资源匹配和播放流程；暂未核对或缺少影片 ID 的作品显示「查找播放资源」，进入普通片名搜索，由用户选择。返回演员页保留分类和滚动位置，再返回原影片详情。
5. 复用现有搜索入口，输入演员姓名后展示匹配的演员卡片；点击卡片按明确演员身份查看参演作品。影片搜索结果继续展示，人物结果与影片结果分组，避免同名影片或其他演员的作品混入。
6. 首版包含按演员找片；演员大全、关注演员和导演主页不在本版范围内。不增加重复的独立搜索入口。

## 需求与验收标准

| 编号 | 行为 | 验收条件 |
| --- | --- | --- |
| ACT-01 | 详情展示演员卡片 | 顺序沿用已有目录演员姓名；核对当前影片与人物出演关系后启用真实头像和导航。无头像或无法确认时使用人物图标；图片失败不影响姓名。首版不承诺完整演职员表。 |
| ACT-02 | 演员身份准确 | 卡片有明确身份时进入对应演员页。同名演员不合并；只有姓名且无法确定身份时展示姓名，不提供错误主页。 |
| ACT-03 | 查看参演作品 | 支持全部、电影、电视剧；作品与演员有来源可核对的出演或配音关系。导演、编剧、综艺嘉宾关系不混入演员作品。 |
| ACT-04 | 去重与分页 | 同一作品只展示一次；电影和电视剧身份区分。滚动加载下一页，失败可重试且保留已有内容，切换分类不串页。 |
| ACT-05 | 衔接播放 | 点击作品走现有资源匹配。打开演员页不自动更换当前影片；返回保留原播放会话与进度。浏览时暂停或收起遵循现有播放器生命周期。 |
| ACT-06 | 资源可用性 | 沿用目录规则，隐藏已确认无资源的作品。检查未完成或网络异常不当作无资源；点击时继续匹配，失败显示可重试提示。 |
| ACT-07 | 真实表达覆盖范围 | 标题使用「参演作品」，辅助说明「展示已收录作品，已隐藏确认无播放资源的内容」。部分来源数据不得标为全部作品，也不显示虚假的总数。 |
| ACT-08 | 加载、失败与离线 | 首次加载显示占位骨架；失败显示「演员信息暂时无法加载」及重试。已有缓存时保留内容并提示未更新；空数据与请求失败分开处理。 |
| ACT-09 | 空态与筛选 | 来源没有该类作品时提示「暂无已收录的电影／电视剧」。因资源筛选后为空时提示「暂未找到可播放的参演作品」，不能推断演员没有出演过。 |
| ACT-10 | 一致性与可访问性 | 姓名最多两行，作品沿用现有海报组件；卡片具有可读标签和合理点击范围。头像缺失时不使用虚构人物或生成的人像。 |
| ACT-11 | 按演员搜索作品 | 输入演员姓名能找到具有明确身份的演员卡片，选择后展示其参演作品。同名演员分别展示，由用户选择；人物查询失败不清空正常的影片搜索结果，不把片名搜索结果直接标为演员作品。 |

首页的高分推荐门槛不直接套用到演员作品页，以免低评分作品被误认为没有出演；此项是首版建议。
