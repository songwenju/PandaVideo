# 播放器启播优化与对标

## 范围

本次实现下一集预解析、平台数据预加载和启播测量，继续复用当前播放链路。主要优化同线路下一集的切换；随机跳集、换影片、换线路仍按正常路径加载。人工体验验收与真实公网 A/B 尚未完成。

## Spec 与验收

- START-01：切集继续复用活动播放链路，下一集预解析结果可跨越正常观看时长使用；临近片尾刷新较旧结果。解析失败不影响当前视频，实际选中时重试。
- START-02：仅预加载同线路下一集，目标为约 3 秒媒体数据；不得提前出声、改变播放进度、触发下一集系统播放元数据。停止、隐藏视频且未启用音频模式、关闭及切换无关内容时释放预加载。
- START-03：Android 使用 Media3 原生预加载源并在播放服务接管；iOS 预热下一集的 AVPlayerItem 资产，在唯一 AVPlayer 上接管。暂停意图、倍速、音频模式、线路切换位置及 PiP 必须保留；不支持或准备失败时正常加载。
- START-04：分别记录请求到解析、原生准备、首帧耗时和预加载命中。按场景、协议、设备及冷/热启动分组；失败、未显示首帧、取消、纯音频不能混入成功 TTFF。
- START-05：运行共享层测试、Android APK 构建安装、iOS Framework 构建；受控媒体验证预加载接管和真实解码首帧。测试网络数字不代表公网线上效果。

## 技术方案

共享层继续只认识 MediaSource 和 PlayerController。新增可选预加载接口以及不含 URL/标题/token 的启播样本，不引入网络上报依赖。按完成时间计算预解析有效期，并在片尾窗口刷新。预加载资源由平台持有，当前视频优先。平台播放器就绪与首帧显示分别记录，禁止将 Ready 当作 TTFF。

预解析有效期初始设为完成后 5 分钟；进入剩余 60 秒窗口且候选完成超过 45 秒时重新解析。没有来源提供的可靠过期时间，这些值属于工程策略，不能保证签名 URL 永不过期；原有失败换源恢复继续保留。随机跳到未预测的集数或另一部影片仍走正常加载。

本地样本最多保留 50 次，记录解析命中和数据命中两个不同字段。Android 首帧回调配合启播阶段 25 ms 的播放推进检查；iOS 显示层与播放推进检查精度约 50 ms。已有进度更新不写高频日志。诊断用 rebufferMs 暂时包含 seek 等等待，不能当作排除了 seek 的 Mux 卡顿率或与其 0.5% SLO 直接比较。

Android 沿用播放服务的单个 ExoPlayer。DefaultPreloadManager 与播放实例通过同一 Builder 创建，共享 LoadControl 和 OfflineMediaSourceFactory。会话命令把候选源交给服务，加载时接管原始预加载源而非重新按 URL 发起下载。保留离线源专用的禁止联网实现。预加载目标 3 秒、编码缓冲目标 8 MiB；这些不是播放器总内存或累计下载量的硬上限。

iOS 会话内只保留一个 AVPlayer，AVPlayerLayer 与 PiP 始终绑定该实例。下一集预热只创建 AVPlayerItem 并异步加载 asset 的 playable/duration 键，不创建备用播放器、不执行 preroll；准备成功后再把 item 交给唯一播放器接管。这不是数据预加载的替代品。此前“备用 AVPlayer preroll 后接管”方案会导致接管集只有声音无画面，且 AVPlayerItem 不能跨 AVPlayer 复用，已弃用。PiP 正在使用时保留当前播放器并冷加载，避免破坏 PiP 绑定。AVPlayerLayer 的显示就绪信号与实际播放推进共同确认视频首帧；采样精度需在验证中注明。

## 主流方案与数据口径

| 来源 | 可核实内容 | 本项目采用方式 |
| --- | --- | --- |
| Android Media3 | DefaultPreloadManager 预加载源；官方示例下一条加载 3000 ms；同 Builder 创建实际 ExoPlayer | 仅下一集，3 秒初始配置 |
| Apple AVFoundation | 关联到播放器后开始加载；preroll 准备媒体管线；默认等待减少卡顿 | 单播放器复用；只预热 item 资产，不降低默认抗卡顿等待 |
| 腾讯云点播播放器 SDK | 区分数据预下载与播放器预加载；预加载有网络和线程开销 | 限制候选数量，当前播放优先 |
| Mux Data | Startup Time 记录播放请求到首帧显示且播放推进；P50/P95；Player Startup Time 单独记录 | 明确区分解析、准备、首帧与整体请求耗时 |
| Mux 开发者指南 | 建议 TTFF <1s 为优秀、<2s 通常可接受；建议初始 SLO 为 P95 <2s、卡顿率 <0.5% | 参考目标，非具体视频 App 的公开实测分布 |

本项目初始工程目标：受控稳定网络下预加载命中切集 P95 <1 秒，公网播放参考 P95 <2 秒；属于本项目目标，不是已达到的结果。预加载优化不应增加卡顿率。真实公网 P95 至少需要按同协议/设备/网络收集足够样本；本次少量设备样本只证明接管链路和测量有效。

未获得爱奇艺、腾讯视频、抖音等 App 在统一设备、片源、网络、广告及冷启动条件下的公开 TTFF 分布，不能声称已经达到这些 App 的实测水平。需要后续相同条件的 A/B 才能作产品性能排名。

## 验证记录

### Android 实机数据

设备 B3110、Android 16，China Debug 构建。两种网络条件各测 MP4/HLS 冷/热各 20 次，共 160 次成功启播；每个协议固定交替执行冷、热，两者复用同一服务播放器。这里“冷”表示未预加载媒体数据，不是 App 进程冷启动。热加载前等候原生预加载完成，其等待发生在切集请求之前。

计时从 `controller.load` 到解码首帧提交给 Surface、处于 Playing 且播放位置大于零；不含地址解析、UI 路由或屏幕合成时间。测试绑定的是测试 Surface，不是实际播放器页面，因此结果是原生播放链路基准，不能直接当作用户屏幕端到端可见首帧时间。完成预加载命中标记均经断言检查。

使用 nearest-rank 分位数，20 个样本中 P50 是排序后的第 10 个、P95 是第 19 个；最大值单列，保留每组首次运行的样本。

| 网络条件 | 协议 | 未预加载 P50 / P95 / 最大值 | 已预加载 P50 / P95 / 最大值 | P95 减少 |
| --- | --- | --- | --- | --- |
| 本机供流，无附加等待 | MP4 | 168 / 265 / 474 ms | 126 / 190 / 229 ms | 28.3% |
| 本机供流，无附加等待 | HLS | 163 / 179 / 812 ms | 123 / 137 / 141 ms | 23.5% |
| 每次媒体响应前固定等待 80 ms | MP4 | 271 / 338 / 540 ms | 143 / 191 / 199 ms | 43.5% |
| 每次媒体响应前固定等待 80 ms | HLS | 333 / 367 / 393 ms | 126 / 162 / 170 ms | 55.9% |

附加等待通过本机测试服务实现，不是公网 RTT；没有模拟 DNS、TLS、带宽限制、丢包、CDN 波动或长视频码率变化。素材约 8 秒，MP4 为 709,212 字节，HLS 为四个约 2 秒分片。固定测试顺序、JIT/解码器预热以及每组仅 20 个样本会影响估计；两种网络条件也不能作为严格的跨组因果比较。原始样本保留于 [无附加等待 JSON](evidence/preload-benchmark-20261112.json) 和 [80 ms 等待 JSON](evidence/preload-benchmark-delayed-20261112.json)，已逐条与实机日志比对。

受控测试中，预加载命中原生首帧 P95 小于 1 秒这一目标已满足。公网“请求到可见首帧 P95 <2 秒”的目标尚未验收，也没有测量真实长视频卡顿率、功耗及流量成本。

### 复现命令

准备相同的短 MP4/HLS 素材后，在仓库根目录启动测试服务：

```sh
python3 mobile/docs/evidence/preload_fixture_server.py \
  --directory /path/to/fixtures --port 18988 --delay-ms 80
adb reverse tcp:18988 tcp:18988
adb install -r /path/to/shared-androidTest.apk
adb shell am instrument -w -r \
  -e class dev.pandavideo.PlaybackPreloadDeviceTest \
  -e preloadFixtureBase http://127.0.0.1:18988 \
  -e preloadRuns 20 \
  dev.pandavideo.shared.test/androidx.test.runner.AndroidJUnitRunner
adb logcat -d -v brief -s System.out:I | rg PRELOAD_BENCH
```

该脚本仅绑定本机回环地址，测试用控制接口只服务受控素材。将 `--delay-ms` 改为 0 可运行无附加等待组。

### 后续公网对标

以实际播放请求为起点，按设备、协议、网络、首次播放/切集、解析命中/数据命中分组，统计 P50、P95、失败率、取消率和预加载命中率。失败样本保留单独计数，不能只统计成功切集来掩盖失败。

先对当前版本启用/禁用预加载做相同素材与网络的 A/B，并扩大每组样本；观察整段观看的卡顿、耗流量和内存。需要比较主流 App 时，在相同设备、网络与相同内容条件下使用屏幕录制或外部采集，统一广告、自动播放和点击起点。最终才能与 Mux 的端到端目标或主流 App 实测作同口径比较。
