# 榜单数据库与海报缓存

首页「精选」与「高分剧集」使用应用内的 SQLite 数据库，分别预置 250 部电影、评分排序前 300 条剧集。数据库保存标题、豆瓣详情地址、年份（来源提供时）、评分、海报地址、主演（来源提供时）及分页顺序。

本次快照来自豆瓣真实榜单与分类接口，包含 550 条记录和 550 张真实海报，资源总计约 14 MB。采集时间、来源及图片数量保存在 `shared/src/commonMain/composeResources/files/catalog-provenance.json`；数据库为同目录的 `catalog-seed.db`。没有使用虚构条目或占位图片。

## 读取与更新

- 首次访问榜单时，将随包数据库复制到平台持久化目录，之后直接从 SQLite 读取；已有数据库不会被随包快照覆盖。
- 数据七天内直接返回本地页，不发起对应榜单请求。过期后尝试更新，403、网络故障或空响应时保留旧数据。
- 成功刷新时，在同一个事务中替换当前页的元数据和影片行，保留其他页的内容。
- 首屏成功后会后台补齐该榜单的剩余页；精选最多 250 条，高分剧集最多 300 条。搜索和播放解析仍访问原来的在线来源。
- 所有分类、热播与筛选分页都持久化到同一数据库；默认高分电视剧筛选复用预置页。额外分页最多保留 256 页，淘汰较旧页时不删除预置榜单。

| 数据 | 新鲜缓存直接读取时间 | 更新失败时 |
|---|---|---|
| 精选、默认高分剧集 | 七天 | 返回原缓存并标记 |
| 其他评分分类 | 24 小时 | 返回原缓存并标记 |
| 最近热播 | 15 分钟 | 返回原缓存并标记 |
| 最新分类 | 30 分钟 | 返回原缓存并标记 |
| 搜索结果 | 15 分钟 | 七天内允许回退，界面显示“缓存结果” |
| 影片详情、简介、剧集与线路列表 | 六小时 | 七天内允许回退 |

搜索按规范化关键词、影视类型及解析规则分别缓存；规则更新后不会误用旧解析结果。搜索和详情共用最多 256 条、16 MB 的有界缓存，单条最多 2 MB；错误页和验证页不写入缓存。播放地址每次实时解析，避免复用失效签名；本功能不下载视频文件。

## 海报

预置榜单的海报从 Compose 跨端资源读取，首次断网启动即可显示。新增、搜索或刷新后未随包的海报由应用专用 Coil ImageLoader 下载，复用磁盘与内存缓存。返回页面后自动预取这一页全部海报，包括未滑动到的卡片；下载最多四个并发任务，页面内容不会等待下载。磁盘缓存上限 256 MB，可按最近使用情况淘汰；随包海报不受缓存淘汰影响。

| 平台 | 数据库 | 下载海报缓存 |
|---|---|---|
| Android | 应用私有 `databases/catalog-v1.db` | 应用 `cache/posters` |
| iOS | `Library/Application Support/PandaVideo/catalog-v1.db` | `Library/Caches/PandaVideo/posters` |
| macOS | `~/Library/Application Support/PandaVideo/catalog-v1.db` | `~/Library/Caches/PandaVideo/posters` |

SQLite 操作和随包图片读取均在后台线程执行；数据库连接按操作关闭，图片加载器在应用组合销毁时释放。应用卸载或清理数据会删除本地数据库，下次安装从随包快照重新初始化。

## 更新随包快照

在 `mobile/` 下运行：

```bash
python3 tools/import_catalog.py
```

若来源暂时不可用，已成功采集的页面保存在 `build/catalog-import-pages/`。可以使用 `--resume` 接着采集。默认命令重新获取页面；只有完整获取两组榜单并验证数量、条目唯一性后，才生成数据库。下载器验证 JPEG、PNG 或 WebP 文件头，并记录没有下载成功的图片数量。更新资源后需重新打包应用。
