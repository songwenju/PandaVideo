# macOS 播控与返回首页修复

日期：2026-11-10

JavaFX 的 JFXPanel 通过 SwingPanel 嵌入播放器。默认 Swing 互操作会把原生面板置于 Compose 内容上方，遮挡进度条、播放按钮和返回按钮，并截获鼠标输入。首次启用混合显示后按钮虽可见，普通鼠标点击仍无响应；无障碍按钮调用能够绕过原生鼠标分发，因此之前的无障碍验证不足以确认鼠标可用。

最终方案使用 `DesktopVideoFrame`：顶部 56dp 导航栏、中央原生视频、底部 92dp 播控栏依次纵向布局，所有按钮和进度条都在原生面板范围之外。移除混合显示设置，入口改为 `compose.layers.type=WINDOW`，倍速菜单使用独立弹窗接收鼠标事件。视频的尺寸绑定中央区域宽高并保持原始比例。

桌面平台启用 `persistentPlayerControls`，播控保持可见。顶部显示片名、返回按钮和独立的“返回首页”按钮。返回首页清理搜索状态、移除播放器导航栈并返回发现页；全屏窗口随播放器页面退出而恢复。全屏选集先恢复普通详情布局，避免选集面板覆盖原生视频。移动端继续使用原有覆盖式播控和自动隐藏交互。

原生跳转和倍速操作后重新应用暂停意图，避免 JavaFX/AVFoundation 在按钮仍显示“播放”时继续推进画面。

## 验证结果

- Android Host：101 项测试，0 失败、0 错误。
- JVM：120 项测试，0 失败、0 错误。
- Android China Debug APK、iOS 真机与模拟器 Debug Framework、macOS DMG 构建通过。
- Android APK 安装至 B3110 成功。
- 直接启动新打包的随心看.app，确认顶部和底部工具栏都在原生视频之外。
- 普通鼠标点击暂停后按钮切换为播放，9:21 的播放时间保持不变。
- 普通鼠标点击倍速按钮打开独立弹窗，点击 1.5× 后标签更新。
- 普通鼠标点击进度条后从约 9 分钟跳转至 82:48。
- 最终包普通鼠标点击暂停、进度跳转和倍速设置通过。暂停时跳转至 82:08 后，倍速切为 1.5×，多个后续观察中时间仍为 82:08，视频帧保持不变。
- 普通鼠标点击全屏和底部退出全屏按钮通过，视频与工具栏同步恢复布局。
- 恢复普通窗口后，普通鼠标点击“返回首页”通过，显示发现首页、继续观看、迷你播控及底部导航。

桌面自动化期间遇到过工具的 `Action root changed` 错误及重复应用实例。全屏顶部“返回首页”的坐标操作被工具错误阻断，未计为通过；普通窗口中的鼠标返回已验证。只统计实际完成并观察到结果的操作；操作报错不算通过。此次没有进行 iOS 真机 UI 验证。
