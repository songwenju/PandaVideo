## 实现

**历史版本说明：**下列原始实现及后续签名、图标记录描述 v0.2 服务客户端。v0.3 已取消服务地址、NAS 状态和下载入口，当前范围与验证见文末“独立移动应用改造”。旧版服务切换测试、QA 服务操作不能作为当前版本验收结论。

- `app` Android 宿主与 China 变体；`shared` Google Android KMP 库和两个 Apple arm64 目标。
- 共用发现、分类、搜索、设置和播放页面。
- Ktor API、JSON 校验、请求取消、来源部分失败、分页去重。
- 连接验证及地址持久化；服务切换取消旧工作并释放播放器。
- Android Media3 / HLS / PlayerView / DataStore；iOS AVPlayer / AVKit / NSUserDefaults。
- 共享播放会话校验媒体编号，防止迟到事件和重复结束导致错误连播。
- Xcode 直接集成静态 Framework，不使用 CocoaPods。

工程不再使用 Expo。旧草稿备份位于 `/tmp/pandavideo-rn-backup`，不会参与构建，临时目录由系统管理。

## 版本与环境

版本锁定在 `gradle/libs.versions.toml`，Gradle Wrapper 与之共同验证。AGP 9.1.0 的实际构建检查要求 Gradle 9.3.1，初次使用 9.3.0 已按该错误修正。JDK 使用 Android Studio 自带 21。

文档候选 Compose 1.12.2、Navigation 2.10.0、Coil 3.6.3 及 Ktor 3.6.1 引入的 OkHttp 5.5.1 实际要求 compileSdk 37；本机 API 37 不可用。因此改为 Compose 1.10.3、Navigation 2.9.2、Coil 3.3.0、Ktor 3.3.3，Media3 1.9.3、Activity 1.12.4、DataStore 1.2.1，保留 Kotlin 2.4.21，重新联合构建。没有跳过 AAR SDK 检查。

Android 最低 API 26，iOS 最低 15。Android 本机 SDK API 36；Xcode 27.2 的 iPhoneSimulator 27.2 SDK 已完成 Kotlin/Native 链接及 Swift 宿主编译。工程只构建 arm64，与 Apple Silicon 模拟器及 iOS 真机目标一致。

### iOS 启动黑屏与模拟器复验

用户通过 Xcode 安装启动后报告黑屏。`devicectl device info apps` 已确认 iPhone 上存在 `dev.pandavideo` 0.1.0 (1)，此前未安装状态已改变。

原包通过 `simctl launch --console-pty` 复现：

```text
Uncaught Kotlin exception: kotlin.IllegalStateException:
Error: Info.plist doesn't have a valid CADisableMinimumFrameDurationOnPhone entry
at androidx.compose.ui.uikit.PlistSanityCheck...performIfNeeded
```

问题：Android Manifest 未声明 icon，iOS 没有 AppIcon 资源集。现在沿用 `frontend/static/favicon.svg` 的绿色渐变、播放符号及阴影设计。

## 独立移动应用改造（v0.3）

日期：2026-11-09。用户确认将内容能力内嵌到 Android/iOS 应用，并明确“应用不需要触发下载 NAS，只有网页端需要”。

### 当前实现

- 替换 `NasApi` 为 `ContentRepository`：设备直接访问豆瓣榜单/分类、阳光电影搜索/详情/播放页面。
- 公共 Kotlin 内静态读取 HTML 和播放器 JSON，支持 URL / Base64 解码，校验来源页面、剧集所属影片、播放授权字段和媒体类型。
- 发现页启动即加载，分类/搜索无需配置地址；关于页替代服务设置页。
- 删除移动端 NAS/迅雷状态、服务地址存储接口、搜索令牌与复制下载链接；现有旧地址不再参与运行。
- 保留原生 Media3 / AVPlayer、线路、选集、倍速、全屏、重试和同线路连播。
- 海报直接请求图片源，带 User-Agent 和来源 Referer；实测豆瓣图片不带请求头返回 418，带头返回 200。
- 公共网络预算 15 秒，最大响应 2 MiB，最多四次同站 HTTPS 跳转。榜单会话缓存最多 64 页，读取失败可展示相同页 stale 缓存。
- 网页端 Python/NAS 下载保持原实现；移动端只接入当前用于在线播放的阳光电影，其他下载来源继续属于网站。

## iOS 播放画面偏移与选集文字换行

- 画面偏移：iOS `PlayerSurface` 通过 `UIKitViewController` 嵌入完整 `AVPlayerViewController`。该控制器面向全屏呈现，内部视频视图按自身安全区容器摆放；在 Compose interop 的非全屏容器中其视频层不跟随分配的 bounds。改为普通 `UIView` 托管 `AVPlayerLayer` 子层，`videoGravity = AVLayerVideoGravityResizeAspect`，并在 `layoutSubviews` 中用禁用隐式动画的 `CATransaction` 把 layer.frame 同步为 bounds、`clipsToBounds = true`。

## 竖屏全屏、详情面板与爱奇艺风格播控

2026-11-10：针对“全屏没有自动横屏、全屏应可看详情、播控 bar 参考爱奇艺”三项反馈完成改造与验证。

### 改动内容

- **平台差异化全屏方向**：
  - **iOS（iPhone 真机，自动横屏）**：`IosPlatform.fullscreen` 进入全屏时通过 `UIDevice.setValue(orientation)` + `attemptRotationToDeviceOrientation()` 切换到 `LandscapeRight`，退出恢复 `Portrait`，让横屏电影在横屏窗口内铺满。前提是 Swift `AppDelegate.application(_:supportedInterfaceOrientationsFor:)` 返回 `[.portrait, .landscapeLeft, .landscapeRight]` 且 Info.plist `UISupportedInterfaceOrientations` 已声明横屏（均已满足）。

### 全屏方向方案说明（iOS 自动横屏 / Android 保持竖屏）

全屏方向经历两轮调整，最终按平台形态分化：

1. 初版进入全屏即强制横屏。问题在于竖屏短剧内容不随窗口旋转，在横屏空间内被压成细横带、上下留巨大黑边。
2. 中间版本两端都改为不旋转（竖屏全屏）。但 iPhone 真机上横屏电影仍只能在竖屏窗口内 letterbox，上下黑边过大，观感是“全屏没有充满屏幕”。
3. 最终方案按平台分化：
   - **iOS 恢复自动横屏**：进入全屏转 `LandscapeRight`、退出恢复 `Portrait`。横屏电影在横屏窗口内基本铺满，符合 iPhone 用户对全屏播放器的预期；`AVPlayerLayer` 用 `ResizeAspect`，竖屏内容仍按比例居中、不会被拉伸变形。
   - **Android / PICO 保持竖屏不旋转**：`requestedOrientation` 不被修改，仅切换系统栏。PICO VR 面板始终竖置渲染（`mCurrentRotation=ROTATION_0`），强制横屏无意义，也规避了 SpaceOS 对 `UNSPECIFIED` 不更新活动记录的兼容问题。

PICO 实测（B3110，《盗梦空间》）：进入全屏后 `mCurrentRotation=ROTATION_0`，视频层铺满屏幕、系统栏隐藏，「锁定」按钮常驻左侧；点底栏退出全屏后回到内嵌 16:9 + 详情面板布局，播放进度保留（7:17 / 149:21）。iOS 模拟器无辅助功能授权，无法自动点击进入全屏，横屏旋转与铺满效果需在真机 Xcode ⌘R 后人工确认。
