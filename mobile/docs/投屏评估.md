# 随心看投屏评估

2026-11-10。对应功能清单 L「投屏评估」，本交付是接入决策与验收范围，不代表已实现设备发现和远端播放。

## 结论

建议 iOS 优先接入系统 AirPlay 路由选择器，中国 Android/PICO 单独验证 DLNA/UPnP 接收器兼容性，具备 GMS 的 Android 发行版本再接入 Media3 Cast。现阶段保持本地播放器，不新增无法工作的投屏入口。

## 项目证据

- Android 使用 Media3 1.9.3、MediaSessionService 和 MediaController，服务已拥有本地 ExoPlayer。Cast 应接在该服务内，由同一个媒体会话管理本地/远端切换。
- 本次连接的 PICO B3110 上，`pm list packages com.google.android.gms` 没有返回包；当前已知设备不具备可确认的 GMS 环境。不能据此推断所有 PICO 或中国 Android 设备都不支持。
- iOS 使用 AVPlayer/AVPlayerLayer，系统音频会话设置为 Playback；现有音量 MPVolumeView 隐藏 route button，不是用户可见的投屏选择入口。
- 当前未连接 Chromecast、AirPlay 接收器或 DLNA 电视，无法声称任何协议的实际播放已通过。

## 方案对比

| 方案 | 当前适配点 | 限制 | 建议 |
| --- | --- | --- | --- |
| AirPlay | AVPlayer 支持外部播放；增加 AVRoutePickerView | 需要真机、同网段接收器；源媒体是否可由接收器访问须实测 | iOS 优先 |
| Media3 Cast | 服务内包装 ExoPlayer，MediaSession 绑定 CastPlayer | Google Cast Android SDK 属于 Google Play services；需要接收设备与网络环境 | 独立 GMS 变体 |
| DLNA/UPnP | 新建远端控制实现，接入现有 PlayerController 抽象 | 本项目没有协议实现；HLS、鉴权、SOAP、重连及电视支持情况尚无设备证据 | 中国版候选，先做设备样本验证 |
| 系统屏幕镜像 | 用户通过设备系统控制 | 应用无法保证画质、延迟及连接状态 | 用户可选的系统能力 |

表中协议候选与优先级属于项目工程判断；厂商兼容性没有实测证据。AVPlayer 的默认外部播放属性及 Cast SDK 依赖各以对应官方资料为依据，并非三个独立来源共同验证的兼容性结论。

## 接入边界

设备发现、连接状态、暂停/seek、断开回本地及失败提示由平台负责；共享层继续拥有标题、选集、进度保存、睡眠定时和自动连播。选择远端时先转移位置和播放意图，成功后暂停本地，失败时保留本地。接收器只能收到已经通过现有授权检查的媒体地址；不得发送历史、家长密码或配置 JSON。

## 实机验收

1. 同网段发现/连接/取消，拒绝权限时保持本地播放。
2. MP4 与 HLS 各一条实际授权可播资源，确认接收器直接访问、音视频与字幕行为。
3. 暂停、seek、切集、片尾自动连播、睡眠定时和青少年配额在远端一致生效。
4. 断网、电视休眠、应用后台、接收器断开后恢复正确进度，避免本地与远端同时出声。
5. Android 覆盖 GMS/无 GMS 两种设备；iOS 覆盖真机 AirPlay，模拟器结果不替代真机。

## 官方参考

- [Media3 CastPlayer 接入](https://developer.android.com/media/media3/cast/create-castplayer)：服务内构建、媒体会话、路由按钮与接收设备测试。
- [Google Cast Android Sender](https://developers.google.cn/cast/docs/android_sender)：Cast SDK 与 Google Play services 的关系。
- [Apple AVPlayer allowsExternalPlayback](https://developer.apple.com/documentation/avfoundation/avplayer/allowsexternalplayback)：允许外部播放，默认 true。

查阅日期为 2026-11-10；升级 Media3 时应以目标版本实际 API 为准，不能直接把当前文档示例的新版本号混入 1.9.3 依赖。
